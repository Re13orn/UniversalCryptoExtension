# 场景向导与预设库更新（2026-10-14）

构建 `UCE-Revision=2026.10.14.2`。此前响应编辑的底层能力与部分动作默认值已更新，但向导和预设库没有完整同步；本轮补齐这两条创建入口，并核对生成规则的实际处理行为。

## 确认的遗漏与修复

| 原行为 | 本次修复 |
|---|---|
| “解密响应便于查看”生成 showInEditor=false | 开启响应明文页签，保持 response-display 只展示，不改客户端密文 |
| 向导没有“编辑响应后重加密”场景 | 新增明文编辑响应：decrypt/response-display + encrypt/response-editor-send |
| 请求编辑模板的 editor-send 动作可能在 Repeater HTTP 回调再次执行 | 新增可选 editorOnly；新请求编辑模板设置 true，HTTP send 路径跳过，编辑提交仍执行 |
| Header 签名默认从目标 Header 读取输入，可能签旧签名而不是正文 | 向导和签名预设显式配置 inputSource=request-body |
| Body 签名可能把上次生成的签名再次纳入正文 | 先移除旧签名字段，再签剩余 JSON；顶层字段名称与实际协议仍须核对 |
| 加解密只收一个 key，不说明编码、字段或 IV | 补充密钥编码、封装、密文/明文字段、IV 字段/固定值及其编码；对称内置路径明确仅支持 JSON 字段封装 |
| 同一密钥的双向模板还提供 RSA/SM2，无法表达不同公私钥 | 双向向导仅提供对称算法/编码；单向场景保留 RSA/SM2，复杂公私钥配置到逐步骤编辑器完成 |
| 切换内外部 provider 重置算法和手工方法列表 | provider 变化只更新可用参数展示，保留这些用户输入 |
| Content-Type 空时隐藏，无法设置 | 保留可编辑输入；规则摘要随文本输入更新 |
| 向导直接生成已启用规则 | 生成禁用草稿，摘要说明核对协议后启用 |
| 预设库只有旧 6 项，详情仅名称/ID | 接入 10 个带真实离线 fixtures 的合成样例，显示范围、方向、输入、目标、算法、阶段与说明 |
| 新样例只有 Skill 文件，Burp 创建入口不可访问 | 规则和 fixtures 作为 JAR 资源打包，直接在预设库使用；资源与 Skill 原文件逐字节核对 |
| 预览是裸对象，不含导入元信息 | 输出 schemaVersion/engineBuild/rules 的版本化可导入 JSON |
| 预设添加未持久化 | 添加禁用副本并保存；失败撤销本次内存新增 |
| 已添加项不便生成修改版 | 新增“编辑后添加”，生成独立 ID 的禁用草稿，不覆盖原规则；编辑窗口明确草稿状态 |
| 预设库无法按用途定位 | 搜索名称/算法/阶段，刷新保留查询和选择 |
| 规则页分类固定为几个 processor，无法筛选新样例类别 | 分类从实际规则取得，与表格分类显示一致 |
| 动作编辑器把额外 Boolean/数值参数强转 String，保存可能失败 | 保留未编辑值的类型，并在保存前提交当前单元格编辑 |

## 使用方式

**按场景创建**适合明确的基础协议。选择请求明文编辑、响应只读展示、响应明文编辑、发送前加密或签名，再填写自己的范围、密钥与封装参数。生成后到规则页审核并启用。响应只读场景不会开放 Intercept 修改；需要修改应选择“明文编辑响应”。

**预设库**提供 10 个可验证合成样例。新样例包括文本编码、AES-CBC、PBKDF2/GCM、分离 tag/AAD、二进制 HMAC、内置 HMAC、JSON 字段、原始二进制 GCM、请求/响应共享上下文，以及响应编辑重加密/原请求头 AAD/密文签名。

样例的域名、测试密钥、固定 nonce 和 AAD 是离线协议向量，不是用户服务的真实配置。特别是 GCM 固定 nonce 只用于复核向量，真实协议须确保同一密钥下 nonce 唯一。需要完整正文加密、PBKDF2 或 AAD 时从脚本预设开始；内置对称算法向导不会把 JSON 字段处理伪装成原始 body 加密。可从“预览配置”复制版本化 JSON；“编辑后添加”保留独立草稿 ID。

旧规则不会自动更新或覆盖。旧 editor-send 规则未配置 editorOnly 时，仍在 Repeater HTTP 回调执行；若只供 Universal Crypto 页签修改后提交，可手工勾选“仅在请求编辑器提交时执行”。若规则还承担自动发送明文加密，不应直接勾选，而应明确拆分 send 与编辑动作。

## 验证

完整构建 **375 项单元测试、2 项独立 JVM 打包测试、最终 JAR 18 项密码服务检查**全部通过。真实 AES-GCM 请求模板经过显示、编辑加密、HTTP 发送再解密后得到修改值，未编辑原密文保持不变；旧规则的 Repeater 兼容执行仍被回归覆盖。响应向导产物由独立 JDK AES-GCM 解密核对；Header/Body 签名由独立 JDK HMAC 核对，Body 重签保持稳定。

标准样例和 forward-test 在 source/packaged 各 **34/34** 通过；JAR 内 **20 个规则/fixture 文件**与维护源一致；发布维护脚本 **9 项**通过。
