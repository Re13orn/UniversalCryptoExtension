# UI 隐藏交互缺陷与优化（2026-10-14）

构建 `UCE-Revision=2026.10.14.3`。这轮重点是“看起来能编辑，保存后却改变了其他行为”的问题，以及排序、字体和弹窗链路。新修复经过真实 Swing 表单和处理器回归，未操作运行中的 Burp、未发送真实流量、未修改用户规则文件。

## 确认的问题与修复

| 问题 | 修复 |
|---|---|
| 规则编辑重新创建条件但没有保存 toolSource，可能把 Repeater 限制扩大到其他工具 | 增加可见的工具来源控件；保留现有值及自定义来源 |
| 空值 Header 条件被当作无效行丢掉，改变规则匹配范围 | 保留空值条件；未修改 Header 文本时保留原始条件和值；Header 通配符仍按原引擎语义使用 |
| 内容正则无修改保存时被 trim，可能丢掉有意义的首尾空格 | 保存原始正则文本，并在提交前编译验证 |
| Header 条件非法行被忽略 | 明确指出行号；重复同名条件报错，不悄悄覆盖 |
| rule/action 编辑使用调用方对象，失败或未确认时可能污染草稿 | 从独立副本编辑；构造并校验候选后才发布；取消/失败不改调用方对象 |
| 纯响应规则保存时也警告没有请求动作 | 有任一方向步骤就允许保存；两边都空则明确提示 |
| 优先级仅允许 1–1000，且键入后可能未提交 | 支持规则模型的完整 int 范围，保存前提交输入 |
| 从预设库进入规则编辑再编辑步骤，Dialog 被强转 Frame | 编辑器/向导统一接受 Window；步骤弹窗归属于当前规则窗口 |
| 不在下拉列表中的脚本 execute/process 或旧正文输入别名，被默认选项替代 | 载入时保留原选项，避免无修改保存改变语义 |
| 修改 Script 动作类型会自动换成 Crypto/Signature，脚本配置看似消失 | 显式选用 Script 时保持处理器选择，其他处理器仍使用适当默认值 |
| variableName 与 targetName 两套值冲突，UI 改名字未必改变真实输出变量 | 显示实际生效的变量名，并把改名写入 variableName；真实流水线验证新名称生效 |
| Field 的 fieldPath 与目标名称冲突，UI 改路径仍处理旧字段 | 显示生效路径，保存同步字段路径和操作；真实处理器验证目标字段变化 |
| 动作保存清空整个 config，未暴露的已有参数可能丢失 | 在独立配置副本上更新界面字段，保留其他已有参数；删除额外参数仍生效 |
| 额外参数能覆盖基本页执行阶段/输入来源，展示和实际行为不一致 | 阻止额外参数覆盖这些公共字段，拒绝重复额外键 |
| 签名配置保存一律转 custom，即使用户没有改模板 | 无修改保留原 signContent/模板；用户修改模板时再切 custom |
| 切换到 Base64/Hash 后自动选择 none，切回带密钥算法却不恢复 | 记住并恢复前一密钥来源；载入配置时不进行中途自动改值；external 编码不被强制 none |
| 规则刷新丢失列排序 | 保留排序键、筛选和按 ID 选中的规则 |
| 多选时详情只显示第一条，容易误以为操作只影响它 | 明确显示选中数量、首条详情与批量操作范围 |
| 详情分类与表格分类不一致，且看不到工具限制 | 使用同一分类说明，增加 Tool 范围 |
| 固定行高/标题字号，大字体可能截断文字 | 行高随字体变化；标题保留主题字号；字体监听只注册一次 |
| 工具栏固定高度，水平滚动条可能挤掉按钮 | 按按钮内容和滚动条高度预留空间 |
| 长预设名称截断且缺少状态说明 | 悬浮显示完整名称和已添加/禁用模板状态 |
| 导出规则使用平台默认编码 | 明确以 UTF-8 写入 |

新建普通规则也默认禁用，和向导、预设、导入规则一致；编辑已有规则保留原启用状态。已有文件不会自动迁移。曾通过旧界面保存的规则，若已经丢掉 toolSource，无法从当前文件可靠推断原限制；应根据实际用途检查并恢复。

## 仍可继续改善的展示和实机边界

- 规则基本条件、步骤列表、算法参数仍信息密集，可以进一步按使用频率分组，减少新用户同时看到的选项。
- 部分帮助说明仍是固定中文，没有宣称已完成全界面国际化。
- 实时流量仍最多保留 1,000 条完整快照，超大正文的内存与渲染尚未做容量验收。
- 文件对话框、实际 Burp 主题、高 DPI、键盘焦点及 Send/Forward 必须在 Burp 实机验收。离线 Swing 测试不等于这些环境全部通过。

这些项目作为后续优化或待验收事项，不与已确认、已修复的缺陷混为一谈。
