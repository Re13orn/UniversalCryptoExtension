# 整体复核与修复

构建标识：`UCE-Revision=2026.10.14.5`。复核范围包括规则创建/保存、请求与响应编辑回写、HTTP 回调、实时流量、测试台、帮助与发布校验。以可复现问题为修复依据；未操作运行中的 Burp，未向任何实际目标发送请求，未修改当前用户规则。

## 本轮确认并修复

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| 未处理也改写重复 HTTP 头 | HTTP 上下文把重复头映射为最后一个值，而写回与第一个原始头比较，导致无动作也写回，可能影响重复 Set-Cookie 等 | 只将处理前后真正变化的头写回；未改变的重复头保持原始结构 |
| 编辑器损坏二进制密文 | 脚本返回 `[0,128,255,65]` 等字节数组，经 ProcessingOutcome 的 String 丢失非 UTF-8 字节 | Outcome 保留防御复制的 bodyBytes；请求和响应编辑器按字节检查变化，以 Montoya ByteArray 写回；覆盖 GBK 与解码文字相同但字节不同的情况 |
| 保存失败后规则仍生效 | 新增、编辑、复制、删除、启停、导入先改内存再落盘；失败时内存、列表、磁盘不一致 | 规则锁内构造独立候选，保存成功后一次发布；失败不改变 revision 或触发监听。预设和请求右键向导使用同一入口；普通保存也受同一锁保护 |
| 无操作保存改变匹配范围 | 已有路径 `/api/items/a,b` 被逗号输入格式重新拆成两个路径 | 匹配字段未编辑时原样保留已有 hosts/paths/methods 列表，避免修改名称也改变范围 |
| 测试丢配置和未保存编辑 | 步骤测试另造简化动作，遗漏输入源、阶段、变量名和额外配置，并关闭步骤窗口 | 复用完整 buildAction 草稿；提交正在编辑的额外配置单元格；应用内打开拥有正确父窗口的步骤预览，保留规则和步骤编辑窗，按请求/响应方向及阶段运行真实管线 |
| 刷新丢自定义算法 | editable 下拉列表外的算法索引为 -1，被刷新成默认算法 | 保存列表索引与实际编辑值；普通选项仍按索引适配翻译，自定义或尚未提交的文本按原值恢复 |
| 右键发送到测试台丢上下文 | 只发送 body，脚本/签名取不到原方法、路径和请求头 | 传递完整 HTTP 文本请求，由测试台建立上下文；加解密/字段模式提取正文处理，不把整段请求当正文 |
| 发布校验覆盖不全 | 只要求示例 10 的资源存在，其他预设或 fixture 缺失/过期可能通过 | 核对全部 20 个预设/fixture 文件；工程内核对打包内容与资源逐字节一致；source contract 包含静态资源和测试资源，检测已移除的输入 |
| 历史测试依赖私有目录 | HeaderDerivedGcmResponseChainTest 依赖 用户目录 规则文件，隔离用户目录时跳过/报错 | 改为仓库内合成 PBKDF2 + GCM/AAD 协议规则，取消机器私有文件候选及跳过逻辑；Surefire 使用 target/test-home，与用户设置隔离 |

## 行为与兼容性

旧规则无需因本轮修复修改。`display` / `response-display` 继续只控制展示；请求编辑仍需明确的 `encrypt`、`body/field`、`editor-send`，响应编辑使用 `response-editor-send`。未编辑、失败、无实际加密与只读路径继续保留原报文。

字节修复针对加密输出，不代表文本明文编辑器可以无损编辑任意二进制明文。脚本与规则头部条件仍使用单值 map；本轮保留未改动的重复头，不新增多值头规则 API。原请求头仍独立于响应头，匹配条件的方向没有改变。

“测试当前配置”在应用内使用步骤预览，以完整参数、输入源、目标与执行阶段运行。外部服务和 key lookup 不在离线步骤预览中执行，明确提示不可验证。主测试台的手工参数表单仍是简化处理器试验工具，不能代替完整链路验收。

合成响应链测试独立使用 JCE 生成/验证密文，规则在 Rhino 中执行。它验证插件链路，不声称验证某厂商当前协议，也不再证明用户 用户目录 中其他历史规则版本的正确性。旧日期报告是历史记录，本轮可复核范围以本报告及对应材料为准。
